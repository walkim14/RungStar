# Sounds

Six interface sounds, generated by `tools/make-sounds.py` and committed as 16-bit mono
44.1 kHz WAV. Under 200 KB for the set.

| File | When |
|---|---|
| `move.wav` | The cursor moved to a different item |
| `select.wav` | Something was chosen |
| `back.wav` | A screen or a menu was left |
| `start.wav` | A song is starting |
| `finish.wav` | A song ended |
| `no.wav` | Something was refused |

## Generated, not downloaded

A WAV is a binary nobody reviews in a diff. The generator is forty lines of arithmetic anybody
can read, change and re-run, so the *reasoning* is in the repository rather than only the
result — and there is no licensing question to answer, because there is nothing here from
anybody else.

Three things shape the set, and they are all consequences of where it is heard:

**It plays over music.** Everything sits between 400 Hz and 3 kHz, above the bass and below the
air, so it cuts through a mix without fighting it.

**It is in tune with nothing in particular.** The notes come from a pentatonic scale on A, which
contains no semitone clashes, so a blip landing on top of a song in any key reads as percussion
rather than as a wrong note. A major triad would clash with every song in a minor key.

**A menu blip is heard hundreds of times an hour.** `move.wav` is the shortest and quietest
thing in the set, with a softened attack so it is a tap rather than a click.

**Nothing plays during a song.** There were two more — a sparkle for a golden note and a chime
for a line sung well — and they were distracting. An interface sound is heard *instead of*
whatever else is happening, which is right in a menu and wrong over the thing somebody came to
listen to; and the screen already says both, so it cost the music to say it twice. Starting and
finishing a song still make a noise, because neither lands on top of any singing.

## Changing them

Edit `tools/make-sounds.py`, run it from the repository root, and run:

```
cargo test -p rungstar-platform sfx
```

Those tests are what makes a binary blob reviewable. They assert that every sound is present
and in a format the mixer accepts, that nothing clips or is inaudible, that nothing starts or
ends on a non-zero sample (a click, which is most obvious over music), that the menu blip is
short enough not to drone during a fast scroll, and that nothing in the set is one of the two
that used to play over a singing voice.

Replacing a file by hand works too, as long as it stays mono 16-bit 44.1 kHz PCM — the reader
in `crates/rungstar-platform/src/sfx.rs` refuses anything else rather than guessing, because a
stereo file played as mono comes out at the wrong pitch and half the length, which sounds like
a bug in the game rather than in the file.

## Turning them off

Options → Sound → Interface sounds. Zero silences them. The game also starts and runs normally
with this folder missing entirely; it is just quiet.
